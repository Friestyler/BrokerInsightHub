✅ Overall Instruction for Replit – Campaign & Update Module Data Model
🧠 Unified Concept Name:
Use CommFlow (short for Communication Flow) to represent both campaigns and smart updates, so developers avoid confusion between overlapping types. This abstraction allows us to support flexible use cases like multi-step marketing campaigns and one-time performance updates—while using a single scalable structure.

🧩 Required Data Tables
Use these database tables (relational structure) to support creation, execution, and analytics of CommFlows.

📄 comm_flows
Represents any communication flow (campaign or update), based on a template or custom-made.

Column	Type	Description
id	UUID / PK	Unique identifier
type	TEXT	'campaign', 'update', 'reminder', 'alert', etc.
target_entity_type	TEXT	'partner', 'customer', 'opportunity', 'user'
target_entity_id	UUID	ID of the selected entity
template_id	UUID (FK)	Optional link to a predefined template
status	TEXT	'draft', 'scheduled', 'in_progress', 'sent', 'archived'
created_by	UUID / FK	User who created the commFlow
created_at	TIMESTAMP	When it was created
updated_at	TIMESTAMP	Last modification

📄 comm_flow_emails
Each step (email) in the communication sequence.

Column	Type	Description
id	UUID / PK	Unique email ID
comm_flow_id	UUID / FK	Related commFlow
step_order	INTEGER	Order in sequence (1, 2, 3…)
subject	TEXT	Email subject line
content_blocks	JSON	Email structure with dynamic fields and layout
ai_generated	BOOLEAN	Whether AI generated the content
send_at	TIMESTAMP	Scheduled send time (optional)
created_at	TIMESTAMP	Timestamp of creation

📄 comm_flow_recipients
Links recipients to the flow, tracks per-contact delivery and engagement.

Column	Type	Description
id	UUID / PK	Unique record
comm_flow_id	UUID / FK	Related commFlow
contact_id	UUID / FK	Recipient contact
email_step	INTEGER	Email step this engagement refers to (1, 2, 3…)
status	TEXT	'pending', 'sent', 'bounced', 'opened', 'clicked'
opened_at	TIMESTAMP	When recipient opened email
clicked_at	TIMESTAMP	When a CTA was clicked

📄 templates
Reusable multi-step email flows without recipients/entities.

Column	Type	Description
id	UUID / PK	Template ID
name	TEXT	Template name
description	TEXT	Purpose of the template
created_by	UUID / FK	Author of the template
created_at	TIMESTAMP	
updated_at	TIMESTAMP	

📄 template_emails
Email steps that belong to a template.

Column	Type	Description
id	UUID / PK	Unique email ID
template_id	UUID / FK	Related template
step_order	INTEGER	Position in sequence
subject	TEXT	Email subject line
content_blocks	JSON	Layout/content structure (with optional AI fields)
ai_generated	BOOLEAN	True if AI created the content

📊 Analytics Possibilities (from schema)
From the comm_flow_recipients table, you can easily calculate:

Total recipients per flow

Sent/open/click rate per step or flow

Bounce tracking (future extension)

Compare template performance across flows

🔧 Developer Notes
Ensure content_blocks can store different content types (text, image, link, placeholder values).

Consider indexing comm_flow_recipients.status for fast analytics.

Future-proof: support for SMS, in-app, or WhatsApp messages can reuse comm_flow_emails by adding a channel field if needed.
