## User Story 1: Customer Portfolio Overview Dashboard

**As a** NN Account Manager**I want to** view a comprehensive overview of Amazon's NN insurance portfolio**So that** I can quickly assess their coverage levels, identify gaps, and prioritize cross-sell opportunities during client meetings

### Acceptance Criteria:

- Display customer name prominently in header ("NN Insurance Portfolio Analysis - Amazon")
- Show 4 key metrics in summary cards:

- Total Annual Premium (€2.4M)
- Products Covered ratio (18/28 = 64%)
- Gap Opportunities count (10)
- Categories Covered count (4)



- Include descriptive subtitle explaining the analysis scope
- Use gradient background styling for visual appeal
- Ensure responsive layout for mobile/tablet viewing


### Technical Requirements:

```typescript
interface CustomerSummary {
  customerId: string;
  customerName: string;
  totalPremium: number;
  productsCovered: number;
  totalProducts: number;
  gapOpportunities: number;
  categoriesCovered: number;
  coveragePercentage: number;
}
```

### API Endpoints:

- `GET /api/customers/{customerId}/portfolio-summary`
- Response: CustomerSummary object

## User Story 5: Product Master Data Management

**As a** System Administrator**I want to** maintain the master catalog of NN insurance products by category**So that** coverage calculations remain accurate and new products can be tracked

### Acceptance Criteria:

- Maintain product catalog with hierarchical structure:

- Categories → Products → Variants



- Support CRUD operations on products:

- Add new products to categories
- Update product details
- Deactivate discontinued products
- Modify category assignments



- Automatic recalculation of coverage percentages when catalog changes
- Version control for product catalog changes
- Audit trail for all modifications


### Technical Requirements:

```typescript
interface ProductMaster {
  productId: string;
  productName: string;
  categoryId: string;
  isActive: boolean;
  description: string;
  targetMarket: string[];
  averagePremium: number;
  createdDate: string;
  lastModified: string;
  version: number;
}

interface CategoryMaster {
  categoryId: string;
  categoryName: string;
  description: string;
  sortOrder: number;
  isActive: boolean;
  products: ProductMaster[];
}
```

### Database Schema:

```sql
-- Product Categories
CREATE TABLE product_categories (
  category_id VARCHAR(50) PRIMARY KEY,
  category_name VARCHAR(100) NOT NULL,
  description TEXT,
  sort_order INT,
  is_active BOOLEAN DEFAULT true,
  created_date TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- Products Master
CREATE TABLE products_master (
  product_id VARCHAR(50) PRIMARY KEY,
  product_name VARCHAR(100) NOT NULL,
  category_id VARCHAR(50) REFERENCES product_categories(category_id),
  description TEXT,
  target_market JSONB,
  average_premium DECIMAL(12,2),
  is_active BOOLEAN DEFAULT true,
  created_date TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  last_modified TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  version INT DEFAULT 1
);
```

- Cache critical customer data
- Offline indicators
- Sync when connection restored

```typescript
// Mobile-specific hooks
const useIsMobile = () => {
  const [isMobile, setIsMobile] = useState(false);
  
  useEffect(() => {
    const checkDevice = () => {
      setIsMobile(window.innerWidth < 768);
    };
    
    checkDevice();
    window.addEventListener('resize', checkDevice);
    return () => window.removeEventListener('resize', checkDevice);
  }, []);
  
  return isMobile;
};
```

### Acceptance Criteria:

- Performance targets:

- Initial page load: <2 seconds
- Tab switching: <500ms
- Data refresh: <1 second



- Caching strategy:

- Browser cache for static assets
- Redis cache for frequently accessed data
- CDN for global asset delivery



- Loading states:

- Skeleton screens during initial load
- Progressive loading for large datasets
- Optimistic updates for user actions



- Error handling:

- Graceful degradation for API failures
- Retry mechanisms with exponential backoff
- User-friendly error messages
